# 集まれ仕様書の森

## 企画概要

**『集まれ仕様書の森』**は、かわいい動物たちからシステム開発の依頼を受け、要件定義から公開・運用までを進める、物語型のエンジニアリング・ポートフォリオ企画。

『ワールドアパート』に登場する**16タイプの動物住民**を顧客として登場させる。住民の性格にはMBTIの設定を背景として持たせるが、MBTIの説明そのものを企画の中心にはしない。

## 世界観

- どうぶつの森を思わせる、親しみやすくかわいい動物たちの世界。
- 住民はそれぞれ困りごとや要望を抱え、エンジニアに開発を依頼する。
- 見た目はかわいいのに、開発現場は仕様書・修正依頼・タスクに埋もれている。
- **「かわいい、かつしんどそう」**というギャップを演出する。かわいいデザインなのに、仕様書まみれで社畜のように働く姿がビジュアルの核。

## 企画の目的

1. 架空の顧客からの依頼を起点に、システム開発の工程を実践・記録する。
2. コードだけでなく、要件整理・設計・テスト・運用までをポートフォリオとして提示する。
3. AIを開発工程全体に活用し、その使い方と成果を可視化する。
4. 『ワールドアパート』の世界観とエンジニアリングの学習成果を結び付ける。

## 基本的な進行フロー

1. **住民からの依頼**：困りごと、希望、制約を聞く。
2. **要件定義**：目的・利用者・必要機能・非機能要件を整理し、要件定義書を作る。
3. **基本設計**：画面構成、画面遷移、データの流れなどを設計する。
4. **詳細設計**：処理、データ構造、入力・出力、例外処理などを具体化する。
5. **実装**：設計に基づいて動くものを作る。
6. **テスト**：動作確認と不具合修正を行い、テスト結果を残す。
7. **公開・運用**：完成品を公開し、改善履歴や運用上の気づきを記録する。

各工程で、**AIをどのように使ったか／自分が何を判断したか**を区別して記録する。

## ポートフォリオへの掲載内容

案件ごとに、次の内容をひとまとまりで見せる。

- 依頼主の動物住民と相談内容
- 解決したい課題と開発の目的
- 要件定義書
- 基本設計書・詳細設計書
- 実装した機能と使用技術
- テスト内容・結果
- 完成したWebページやアプリへの導線
- AI活用の記録と、自分の判断・改善点

**「動物から依頼される → 仕様書ができる → 実際に動くものが完成する」**という一連の流れが分かる構成を目指す。

## ビジュアル方針

- かわいらしい動物キャラクターと、柔らかい世界観。
- 机に積み上がる大量の仕様書、散らかった書類、終わらない仕事。
- 動物たちはかわいい表情・造形を保ちながらも、明らかに疲れている。
- 「癒やし系の見た目」と「過酷な開発現場」の対比でユーモアを作る。

## ワールドアパートとの関係

『ワールドアパート』の16タイプの動物住民を、システム開発の依頼主として活用する。各住民の個性は依頼内容やコミュニケーションに反映できるが、タイプ診断の解説よりも**顧客の課題を技術で解決する物語**を優先する。
